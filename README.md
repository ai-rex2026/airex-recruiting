# AI-Rex Recruiting

広告リクルーティング業務（ランキング／比較メディアへの掲載獲得）を、
**AIが下書きし、人は承認するだけ**で回すオペレーション基盤。

要件定義書「広告リクルーティング業務 AI化アプリ 要件定義書 v0.1」に対応する実装です。

## 構成

- Next.js 16（App Router / Server Actions） / TypeScript / Tailwind CSS v4
- Supabase（PostgreSQL / Auth / RLS）
- Claude API（メディア判定・掲載判定・競合抽出・文面生成・返信分類・URL候補提案・Web検索による自動収集）
- Vercel

## 主な画面

`/start`（案件・収集）が**標準の入口**です。ルート `/` およびログイン後は `/start` に遷移します。

**サイドバーは4項目**（案件・収集／承認キュー／メディア台帳＋「管理」グループ：文面テンプレ・設定・監査ログ）に絞っています。
`/queue`（承認キュー）は3タブ構成（**承認待ち／例外対応／送信ログ**）で、例外対応と送信ログはここに統合されています。
案件ごとの画面は**案件詳細ハブ `/campaigns/[id]`** のタブ（収集状況／陣取りボード／打診・返信・掲載／案件情報・KW）から辿ります。
貼り付け収集（`/collect`）は案件詳細「収集状況」タブの各KW行の「貼り付けで取り込む」から使います。
`/start` は**サマリー専用**（案件カードのクリックで案件詳細へ。収集の実行・再開・再収集などの操作は案件詳細側）、
陣取りボードは**閲覧専用**（打診の操作は「打診・返信・掲載」タブ／送信の承認は承認キュー側）です。
`/dashboard` は廃止し `/start` へリダイレクトします。`/board` `/collect` `/outbox` `/exceptions` `/replies` `/placements` などの旧ルートも直接アクセスすれば従来どおり動作します。
また、全画面の上部に**業務フローバー**（① 集める → ② 打診する → ③ 返信・交渉 → ④ 掲載・報告）を表示し、現在地のハイライトと各段階で対応待ちの件数（＋例外件数）を常に確認できます。

| パス | 役割 |
|---|---|
| `/start` | **案件・収集（標準の入口・サマリー専用）**。かんたん開始ウィザード＋案件ごとの収集状況サマリーカード（操作は案件詳細の収集状況タブ） |

| `/audit` | 監査ログ |

## 収集センター（/start）

商品のURL、または商品情報・キーワードのテキストを入れるだけで、
関連する比較サイト・ランキングサイト・おすすめサイトが自動で集まり、陣取り表が出来上がります。

1. **商品を教えてください** — LP URL または商品説明テキストを入力。AIがLPを読み取り、案件情報と検索キーワード（8〜12個）を提案
2. **案件とキーワードの確認** — 提案内容を人が修正・キーワードを取捨選択して案件を作成
3. **自動収集（2段階）** — キーワードごとに ①Claude API の **Web検索ツール**（`web_search`）で検索上位のランキング／比較／おすすめ記事を発見し、②**各記事の本文をサーバー側で取得**して掲載枠（記事内の商品・サービスと順位、自社掲載の有無）を本文から抽出。`/collect` の貼り付け方式と同じ形（serp_snapshot → serp_entries → article_listings → outreach_targets）で陣取り表に反映。既存スナップショットは陣取り表の「記事本文から読み直す」で再抽出できます

収集は `collection_jobs` テーブルでジョブとして管理されます。ウィザードで案件を作成すると
**案件詳細の「収集状況」タブへ遷移し、そこで各KWのジョブが順次自動実行**されます（/start ではジョブを実行しません）。
/start には案件ごとの**サマリーカード**（✅完了／⏳実行中／◻未実行／❌失敗の集計＋KW数）だけが表示され、
「未実行を再開」「全KWを再収集」「（KW単位の）収集／再収集」は案件詳細の収集状況タブから行います。
ブラウザを閉じても状態は残り、完了済みKWの再収集は新しいジョブ・新しいスナップショットとして履歴に積まれます（定点観測）。

- SERP取得は Claude API の Web検索ツールを使用（**O-1 の暫定解**。商用SERP APIへの置き換え可能な構造は維持）。検索は Anthropic のWeb検索API（日本ロケーション固定・ブラウザ/Cookie/プロファイル非依存）で行うため、Google SERP の厳密な順位計測ではありません
- 自動検索にはAPI利用料がかかります（1キーワードあたり数円〜十数円）
- 収集まで自動、**打診対象の確定・送信の承認は人が行います**（自動送信・自動承認はしません）

## 絶対に守る原則（コードで担保）

1. **二重送信しない** — 成功／不確定／営業お断り／手動送信済 の履歴がある打診は送信対象にしない（承認時・ワーカー取得時の両方でチェック）
2. **CAPTCHAは突破しない** — 例外対応キューへ退避
3. **営業お断りは尊重** — メディア単位でフラグを立て、以後の打診から自動除外。解除は管理者のみ
4. **マスタの書き換えは承認制** — AIのURL候補は「未検証」としてメモに残すだけで、台帳への反映は人が行う


## 送信ワーカー連携

送信そのものは外部の Playwright ワーカー（`form-outreach-runner`）が実行します。

```
GET  /api/worker/pull      Header: x-worker-token: <WORKER_TOKEN>
  → {"count":n,"items":[{"attempt_id","channel","to","media","domain","subject","body"}]}

POST /api/worker/report    Header: x-worker-token: <WORKER_TOKEN>
  Body: {"attempt_id":"...","result":"success|uncertain|form_error|url_error|captcha|no_solicitation",
         "detail":"...","evidence_path":"..."}
```

`result` の書き戻しは1回だけ受け付けます（2回目は 409）。
